# Nonstop Example: `packages/localization`

Type-safe user-facing strings (layer 0), generated by i69n from
`lib/messages.i69n.yaml`, plus the global `strings` accessor. It owns copy and
locale selection only: no widgets, no formatting helpers, no dependency on any
workspace package.

Read the root `CLAUDE.md` and `packages/CLAUDE.md` first.

## Public API

Exported from `package:localization/localization.dart`.

| Symbol | Kind | Notes |
|---|---|---|
| `strings` | global getter | `LocalizationProvider.messages`; use `strings.<group>.<key>` |
| `Messages` | generated | Groups: `app`, `generic`, `common` (only `week`, `month`), `auth`, `profile`, `nav` (incl. `explore`), `notifications`, `errors`, `validation`, `developer` (`no_viewer`) |
| `<Group>Messages` | generated | e.g. `ErrorsMessages`, `ValidationMessages`; parameterised keys are methods (`errors.format_exception_message(code, postfix)`, `validation.invalid_key_config(of, key)`) |
| `LocalizationProvider` | static helper | `messages`, `currentLocale`, `supportedLocales`, `isLocaleSupported`, `getBestMatchingLocale(List<Locale>)` |

## Layout

| Path | Responsibility |
|---|---|
| `lib/messages.i69n.yaml` | Source of every string, grouped by area |
| `lib/messages.i69n.dart` | Generated from the YAML. Never edit |
| `lib/src/localization_provider.dart` | Locale selection; always returns English `Messages` today |
| `lib/src/strings.dart` | Global `strings` getter |
| `lib/localization.dart` | Barrel |
| `build.yaml` | i69n builder options: `default_locale: en`, `locales: [en]`, `generate_for: lib/messages.i69n.yaml` |

## Rules

- Keys are snake_case and live under an existing group (`generic`, `errors`, `validation`, ...). A new top-level group becomes a new `<Group>Messages` class and getter on `Messages`.
- Parameterised messages use i69n's signature-as-key form in YAML: `name(String a, String b): "... $a ..."`.
- `LocalizationProvider` supports only `'en'`; `getBestMatchingLocale` returns the first supported language code, else `'en'` (so always `'en'` today). Do not add a locale to `supportedLocales` without adding its translation file and a real lookup.
- `core` reads `strings.errors.user_not_found` for `UserNotFoundException`; renaming a key breaks callers across the workspace. Grep before renaming or deleting.

## Common changes

- **Add a string:** add the key to the right group in `lib/messages.i69n.yaml`, run `dart run melos run generate:i69n` (build_runner + `dart format lib/messages.i69n.dart`), then use `strings.<group>.<key>`. Commit the YAML and the regenerated `.i69n.dart` together.
- **Add a parameterised string:** `key(String x): "text $x"` in the YAML, regenerate, call `strings.<group>.key(x)`.
- **Add a locale:** add `lib/messages_<code>.i69n.yaml`, list the code under `locales` and the file under `generate_for` in `build.yaml`, regenerate, then list the code in `supportedLocales` and pick its generated class in `messages` (the steps in the `LocalizationProvider` doc comment); extend `test/localization_test.dart` for the new match and fallback.

## Tests

`test/localization_test.dart` covers `getBestMatchingLocale` (supported, unsupported, empty list), `currentLocale`, `messages`, `supportedLocales` and `isLocaleSupported`. Generated `*.i69n.dart` is excluded from the coverage gate (`tool/coverage.dart`), so new keys need no tests; new logic in `lib/src/` does.

Run: `dart run melos exec --scope=localization -- flutter test`. `dart run melos run coverage` must stay 100%.

## Gotchas

- `messages.i69n.dart` is generated (`// GENERATED FILE, do not edit!`) and is skipped by both `tool/check.dart` and `tool/coverage.dart`. Never hand-edit it; `.claude/hooks/guard_generated.sh` blocks the edit.
- Shared button/state copy (`ok`, `cancel`, `save`, `try_again`, ...) lives in `generic`; `common` holds only `week` and `month`. Do not re-add duplicates to `common`.
